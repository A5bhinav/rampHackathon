# packages/evidence: canonical JSON and the hash chain, Python side

**Owner: Abhi. Partner reviewer: Sami.**

The database owns the chain (`supabase/migrations/audit/0001_evidence_chain.sql`). This
package is the Python mirror of its three rules, so services can build an envelope,
pre-compute its content hash, verify a chain they read back, and prove that both languages
agree. If Python and SQL ever disagree, `append_evidence()` refuses the write when the
caller passes its expected content hash.

## The contract

| Step | Rule |
|---|---|
| `body_jcs` | RFC 8785 canonical JSON of the envelope: `rfc8785.dumps(envelope)` |
| `content_hash` | `hex(sha256(utf8(body_jcs)))` |
| `hash` | `hex(sha256(utf8(prev_hash + content_hash)))`, two hex strings concatenated |
| genesis | the first event's `prev_hash` is 64 zeros |
| numbers | integers only; amounts as integer cents or strings |

The golden vectors are `packages/contracts/vectors/evidence-chain.json`, generated by
`packages/contracts/scripts/make_vectors.py` and replayed by `supabase/tests/005_hash_vectors.sql`.

## What to build

- `envelope.py`: typed builder for the envelope (`EvidenceEnvelope`, Pydantic) that validates against the JSON Schema and refuses floats.
- `hashing.py`: `jcs()`, `content_hash()`, `chain_hash()`, `GENESIS`.
- `verify.py`: `verify_chain(rows)` for rows read from `audit.evidence_events`, returning the first bad seq and why, with the same four checks the SQL function makes (seq gap, prev linkage, content hash, chain hash).
- `redact.py`: the log and trace redaction the design requires: an allowlist of fields, any run of six or more digits masked, never a request body. Used by every Python service.
- `witness.py`: writes the chain tip (`audit.chain_tip`) next to each scorecard so it can be committed to GitHub as the outside witness (ADR-7). Production path, not built: a daily Merkle root timestamped by an outside authority.

## Tests you owe

- Every vector in `evidence-chain.json` reproduces in Python (this is the `hash-vectors` CI layer).
- `verify_chain` points at a row whose `body_jcs` was edited, and at a row whose `prev_hash` was swapped.
- Redaction masks digits inside nested structures and never logs bodies.

## Start here

`src/dialback_evidence/hashing.py` first, then make `tests/test_vectors.py` load the vectors
file and pass. Everything else builds on those two functions.
