# Real PDFs, Part A (spec 0092) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real digital PDFs flow through the unchanged ledger pipeline: a lab renderer writes any page model to a PDF, a product reader reads a PDF back into the page model with visibility decided per character, and an exact render-then-read round trip proves it on the corpus, the demo seed and spec 0052's documents.

**Architecture:** `evals/src/dialback_evals/pdfrender.py` (lab only) draws each span as one reportlab text object in an embedded font, plus optional planted tricks. `packages/ledger/src/dialback_ledger/pdf.py` (product) reads characters with pdfplumber, classes each one (`off_page`, `tiny`, `white`, `no_ink`, else `visible`), groups them into lines and spans, and decides ink by rendering the page with PDFium with and without each text object. `ingest_pdf` hands those pages to the existing `ingest()`; nothing after text changes.

**Tech Stack:** Python 3.13, uv workspace, pdfplumber 0.11 (pdfminer.six), pypdfium2 5.x (PDFium), numpy (pixel diff), reportlab 4.x or later and fontTools (lab only), pytest, Postgres 16 (DB tests via Docker on this Mac).

**Spec:** `specs/0092-real-pdfs-and-scans.md`, Part A only (D1 to D10, the Part A acceptance list, the Tests table, "Calls made after the builder check"). Conventions from `specs/0022-ingestion.md` and `specs/0049-llm-document-reader.md`.

## Global Constraints

- Part B is out of scope: no OCR, no vision call, no pixel check, no `DIALBACK_SCANS`, no `unverified` producer, no `unconfirmed_digits_only` producer (D11 to D17).
- ASCII only in everything written: no em dash, en dash or other non-ASCII dash.
- The page model is the interface: `{width, height, spans: [{text, x, y, size, color}]}`, `x` = first character's left edge, `y` = pdfplumber's `top`, both in points from the page's top-left, `color` = `#rrggbb` (D1).
- A span may carry `ink: false`; `visibility.classify` reads it as `no_ink`, after the existing classes (D1).
- Hidden order: `off_page`, `tiny` (under 4 points), `white` (every channel `F0` or above; unconvertible colour counts as white), `no_ink` (D3).
- Refusals fail the whole document closed with `PdfRefused(reason)`; nothing of it is stored (D4).
- Limits: over 20 pages, over 10 MB (`10 * 1024 * 1024` bytes), over 20 seconds (D4).
- `sha256` of a PDF document = SHA-256 of the file's bytes; `extractor_version` = `pdf-<reader version>/<labeler version>` (D5).
- The product never imports `dialback_evals` (D6). Ledger tests may (they need the renderer).
- Round trip bar is exact: same text, same visibility, same colour, `x` and `y` within 0.5 pt, `size` within 0.1 pt (D7).
- Fictional phones only (NPA-555-0100 to 0199). Team phones are never committed; `--out DIR` must be outside the repo (D9).
- Never read `.env`; never hand-edit `packages/contracts/generated/`; contract changes only in their own PR; no live API calls.
- Every `ingest()`, `ingest_all()` and `ingest_pdf()` call in a test passes `reader=` explicitly (the guard in `test_ingest.py`, extended in Task 6).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; PR bodies end with the Claude Code generated line. Stage files by name.

## Builder's values (pinned here, each pinned again by a test)

| Name (in `pdf.py`) | Value | Why |
|---|---|---|
| `READER_VERSION` | `"1"` | so `extractor_version` reads `pdf-1/stub` |
| `MAX_PAGES`, `MAX_BYTES`, `TIME_LIMIT_SECONDS` | `20`, `10 * 1024 * 1024`, `20.0` | D4 |
| `INK_SCALE` | `3` (216 dpi) | small glyphs still cover whole pixels |
| `INK_DIFF` | `16` | a pixel has ink when some channel moves by 16 or more: the same contrast the `F0` white rule allows |
| `WORD_GAP` | `1.0` (times the left character's size) | intra-span gaps are 0; the page model's cells are 100+ pt apart |
| `BASELINE_TOLERANCE` | `0.5` pt | one baseline per page-model span |
| `NARROW_POINTS` | `0.8` pt | a non-whitespace character narrower than this is `tiny` (see Review Focus) |

Measured in the planning spike (Nov 10, PDFium 150, pdfplumber 0.11.9): visible black text gives a max diff of 253 to 255; text under a white rectangle, under a white image, in render mode 3, in mode 3 over a black bar, clipped away, and in a colour equal to the shape under it all give exactly 0.

## Rulings made while planning (report each in the PRs)

1. **`reasons.py` and `apps/web/src/data/corpus-results.json` go in the contract PR.** `test_reasons.py` requires `REASON_TEXT` to equal the schema's `Reason` enum and the OpenAPI `reason_text` map lists every reason, so the sentence must land with the enum; the results file embeds the sentences and is regenerated by its script. No rule behaviour changes.
2. **The migration is `0004_...`**, because open PR #120 adds `ledger/0003_selection_withheld.sql`. `migrate.py` applies new files by name, so a gap is harmless.
3. **`store.change_context` and `select()`'s `unverified` handling stay for Part B.** In Part A nothing produces `unverified`; today's `select()` already reads any non-`visible` sighting as hidden (`hidden_text_only`), which fails closed.
4. **`ingest_pdf` takes `custody` positionally**, mirroring `ingest(document, custody, ...)`: the spec's signature omits it, but an attachment's custody needs its parent. `ingest_all` gains `pdfs: Mapping[str, bytes] | None` so batches resolve custody as today.
5. **Per-character ink.** D3 classes characters, and D2 splits spans where the class changes, so the ink test is run per character: each top-level text object is hidden once, and each of its characters has ink if its own box changed. A character PDFium can't tie to a top-level text object, or a page whose PDFium and pdfplumber character sequences disagree, is `no_ink` (D3's "can't isolate" rule).
6. **"White over a white shape" is `white`**, because the white rule comes first in D3's order. The ink rule's version of the case is a non-white colour over a shape of the same colour, which is `no_ink`. Both get a test.
7. **Whitespace never splits a span.** A whitespace character takes the class of the nearest preceding non-whitespace character in its segment (the following one at the start), so a hidden number keeps its spaces and is observed whole, as gate A requires.
8. **Annotations:** any annotation other than `Link` refuses the page (`annotation`); a `Widget`, or a document form type other than none, refuses as `form_field`. A Link shows no text.
9. **More fail-closed cases, beyond D4's list:** a page with `/Rotate` other than 0 is refused (`rotated`): pdfminer and PDFium would disagree on its frame. A character whose text matrix isn't upright and unmirrored (`b == c == 0`, `a > 0`, `d > 0`) is `no_ink`. Unmapped glyphs (`(cid:N)`) become U+FFFD, which holds no digit (D4).
10. **Colour spaces:** only `DeviceGray`, `DeviceRGB` and `DeviceCMYK` with the right number of values in [0, 1] convert; everything else (Pattern, Separation, ICCBased, Indexed, DeviceN, Lab, odd values) counts as white. CMYK converts naively: `r = 255 * (1 - c) * (1 - k)`.
11. **Team phone and the LLM reader.** Spec 0049 D5 says a team phone never reaches the model, but D9 puts the team phone in the PDFs. So `demo load --pdf DIR` (an explicit folder, which may hold a team phone) is refused under `DIALBACK_READER=llm`; `--pdf` alone (the committed, fictional PDFs) works in both modes.
12. **The D10 plant's job key is `lab-pdf`**, a new entry in `known.JOBS`, held by `evals/tests/test_pdf_tricks.py` (which lab-smoke's pytest step runs). Putting it under `lab-smoke` would make `lab run` report it as stopped.
13. **Renderer plants beyond the spec's four tricks**, read only by the renderer and used only by the tests (listed in Task 2's Interfaces): `under`, `color_space` plus `color_value`, `hscale`, span `rotate`, and page-level `crop`, `rotate`, `annotations`, `form_field`, plus `render_pdf`'s `compress` and `encrypt`. They compose: "invisible over a black bar its own size" is `trick: invisible, under: #000000`.
14. **Timeout is cooperative:** the deadline is checked after each page and each ink render. A single pdfminer page parse can't be interrupted; the 10 MB cap bounds it. Reported as a known limit.
15. **Gate tests through PDFs live in the ledger's tests** (the Tests table), importing the lab renderer; the product code never does.
16. **#125 merged into main on Nov 10, during planning,** so nothing waits: D6's `docgen` fix goes in the first code PR, as D6 says, and the 0052 sources join the overlap check (Task 2), the round trip (Task 5) and the `lab docs` equivalence (Task 6). The 0052 round-trip sources are every frozen case under `evals/docs-generated/`, plus `draw_docs(examples=200, seed=s)` and `draw_worlds(seed=s)` for `s` in 0 to 4 (200 per seed is the builder's count, as in D17's development set).
17. **`lab docs` through PDFs:** `docgen.run()` takes no ingest hook and G7 calls `bridge.ingest_all` directly, so the equivalence test swaps a PDF-reading `ingest_all` into both `dialback_ledger.ingest.ingest_all` (which `check_doc` imports lazily) and `dialback_evals.bridge.ingest_all`. No lab code changes for it.

## Review Focus

1. **A span whose box straddles the page edge** (origin inside, last glyph outside) must never come back `visible`: its characters are `off_page`, and when `classify` would read its origin as inside the page, the reader sets `ink: false` so it stays hidden. Test in Task 3: `test_a_span_straddling_the_edge_is_hidden`.
2. **A crop box smaller than the media box:** text outside the crop box is `off_page`, and coordinates and page size are the crop box's. Test in Task 3: `test_text_outside_the_crop_box_is_off_page`.
3. **Horizontally squashed digits** (a text matrix `a` of 0.05, or `Tz 5`) are 10 pt tall but a smudge wide; size alone says visible. The narrow rule makes them `tiny`. Test in Task 3: `test_squashed_text_is_tiny`.
4. **Whitespace inside a hidden span** must not split it, or the hidden number disappears instead of being observed hidden (and `hidden_text_only` can't be shown). Test in Task 4: `test_spaces_keep_a_no_ink_span_whole`.
5. **A page-model `ink` value that isn't exactly `true`** (`"false"`, `0`, `null`) must read as `no_ink`, never visible. Test in Task 3: `test_an_ink_flag_other_than_true_is_no_ink`.

- [ ] **Step 3: Implement** in `pdf.py` (ink comes in Task 4; until then `_ink` returns True for every character, so the trick tests there will fail first). Per page, in pdfplumber's frame:
  - crop box from `page.cropbox` (top-left frame); output `width`, `height` = crop box size; `x = x0 - crop_x0`, `y = top - crop_top`, rounded to 3 decimals.
  - per character, first match wins: not inside the crop box: `off_page`; `size < 4` or (non-whitespace and `x1 - x0 < NARROW_POINTS`): `tiny`; `_color(char)` is None or every channel `>= 0xF0`: `white`; matrix not upright and unmirrored: `no_ink`; `_ink` false (non-whitespace only): `no_ink`; else `visible`. `(cid:N)` text becomes `"\ufffd"`.
  - lines: cluster by baseline (`matrix[5]`) within `BASELINE_TOLERANCE`, top to bottom; characters in x order.
  - segments: split where `next.x0 - prev.x1 > WORD_GAP * prev.size`.
